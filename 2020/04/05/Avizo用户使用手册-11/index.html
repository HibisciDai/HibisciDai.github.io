11 自动化、定制、扩展

11.1 模板项目

本节描述模板项目(Template Projects)的用法。

11.1.1 模板项目说明

模板项目可用于简化在一组相似数据上的重复性任务。模板项目是某个原始项目的副本，它可以被重新应用到同类型的其他数据上。

11.1.1.1 如何保存模板项目

要创建模板项目，请从File菜单中选择Save Project As Template。会出现一个输入选择对话框，列出所有可能的模板输入（即当前所有的数据对象）。模板输入代表一个在该模板被执行时必须提供的数据集。你可以更改每个模板输入的标签。该标签应当是通用且有意义的，因为它会在模板执行期间被显示出来。默认标签是原始数据对象的名称。注意：未被使用的数据对象默认会被过滤掉，但你可以通过选择Include unused data选项把它们包含进模板项目中。

如果该模板恰好只包含一个输入，会有一个对话框询问你是否希望把该模板与这种数据类型关联起来。如果你单击OK，那么该模板将对所有同类型的数据对象在其右键菜单(Templates子菜单)中可用。

最后，会出现一个文件对话框来命名输出文件。该文件名也就是模板的名称，即将出现在Templates菜单中的名称。内置的模板项目存储在文件夹share/templates中，但你可能没有足够的权限在该目录中创建新文件。

图 11.2：如果模板只有一个输入，则可以进行数据类型关联。

你可以把自定义模板保存在任何目录中。它们会在每次Avizo启动时被自动重新加载。

11.1.1.2 如何使用模板项目

内置的模板项目和已知的自定义用户模板项目会在Avizo启动时被自动加载。加载模板并不意味着实例化该模板项目。模板项目只在用户需要时才被创建，例如通过Project > Create Object...菜单。有一个例外：如果用户通过Open Data对话框加载某个模板文件，该模板资源会被加载，然后被执行。

如果该模板与某种数据类型相关联，你可以使用该类型数据对象的右键菜单来创建一个实例。在这种情况下，该模板会立即使用所选的数据对象被创建出来。

对于其他模板，你可以从Project > Create Object...菜单的Templates子菜单创建一个实例。该模板也可能出现在宏按钮列表中。在这种情况下，模板执行时会出现以下对话框：

图 11.3：模板项目运行对话框。

每个模板输入都会显示其模板输入名称，以及一个用于选择将被用于该输入的数据集的组合框。每个组合框中列出的候选项会按其数据类型进行过滤。你可以通过取消选择Check input type选项来禁用该过滤，从而显示Project View中存在的所有数据。如果没有合适的数据对象，该组合框将为空。你总是可以选择<load file...>项来显示一个文件打开对话框并选择某个数据文件。

对颜色图的特殊处理：默认情况下，已经在Project View中的颜色图会被按原样重用。这意味着，例如模板项目中的对象可能会受到范围变化的影响。你也可以通过选择Independant colormaps选项，选择不与已有对象共享颜色图。

11.2 配方

Avizo允许创建用户自定义的配方(recipes)，用于自动化某个复杂场景，其中会用到多个工具和工作区。这些配方定义高层次的工作流，例如从图像中提取用户自定义的统计信息。更多信息请参阅第5章 创建配方以自动执行工作流。

11.3 Avizo启动

本节描述可用于Avizo启动的一些选项：

  • Command Line Options 命令行选项
  • Environment Variables 环境变量
  • Avizo start-up script Avizo启动脚本

11.3.1 命令行选项

本节描述Avizo所能识别的命令行选项。一般来说，在Unix系统上，Avizo是通过位于子目录bin中的start脚本启动的。通常，该脚本会被链接到/usr/local/bin/Avizo或类似位置。此外，用户也可以定义一个指向bin/start的别名Avizo。

在Windows系统上，Avizo通常通过开始菜单或桌面图标启动。不过，也可以通过调用bin/arch-Win64VC12-Optimize/Avizo.exe来直接调用Avizo可执行文件。在这种情况下，所能识别的命令行选项与Unix系统上相同。

Avizo的语法如下：

在命令行中指定的数据文件会被自动加载。除数据文件之外，也可以指定脚本文件。这些脚本将在程序启动时被执行。

支持以下选项：

  • -help：打印命令行选项的简短摘要。
  • -version：打印Avizo的版本字符串。
  • -no_stencils：告知Avizo不要在其3D图形窗口中请求模板缓冲区(stencil buffer)。在某些低端PC显卡上，可以设置该选项以利用硬件加速。
  • -no_overlays：告知Avizo不要在其3D图形窗口中使用覆盖平面(overlay planes)。如果你在远程显示上重定向Avizo时遇到问题，请使用该选项。
  • -no_gui：在不打开任何窗口的情况下启动Avizo。该选项对于在批处理模式下执行脚本很有用。
  • -logfile filename：使控制台窗口中所打印的任何消息同时被写入指定的日志文件。特别是与-no_gui选项结合使用时很有用。
  • -depth number：该选项仅在Linux系统上受支持。它指定深度缓冲区的首选深度。Linux系统上的默认值是16位。
  • -style={windows | motif | cde}：该选项设置Avizo的Qt用户界面的显示风格。
  • -debug：该选项仅适用于开发者版本。它会使本地包以调试模式执行。默认情况下将使用优化后的代码。
  • -cmd command [-host hostname] [-port port]：向一个正在运行的Avizo应用程序发送Tcl命令。可以选择性地指定主机名和端口号。在命令能够被接收之前，你必须在Avizo的控制台窗口中键入app -listen。
  • -clusterdaemon：在集群从节点上作为VR守护进程启动(Avizo XScreen Extension)。它可能会被某个服务所替代。更多信息参见在线文档。
  • -tclcmd command：在启动中的应用程序中执行该Tcl命令。
  • -edition { LiteEdition | AvizoEdition | FEIEdition }：以特定的版本启动Avizo。

11.3.2 环境变量

执行Avizo并不需要特殊的环境设置。在Unix系统上，某些环境变量（例如共享库路径或AVIZO_ROOT目录）由Avizo的启动脚本自动设置。用户也可以设置其他环境变量以控制某些功能。这些变量列在下面。在Unix系统上，环境变量可以使用shell命令setenv(csh或tcsh)或export(sh、bash或ksh)来设置。在Windows上，环境变量可以在系统属性对话框(Microsoft Windows)中定义。

  • AVIZO_DATADIR：一个数据目录路径。该目录将被用作文件对话框的默认目录。请注意，为了快速访问多个位置，你可以使用操作系统，例如把目录添加到文件对话框的收藏位置列表中，或者使用一个包含指向其他目录的快捷方式或链接的目录。
  • AVIZO_TEXMEM：以兆字节为单位指定纹理内存的数量。如果未设置该变量，系统会应用某些启发式方法来确定某个系统上可用的纹理内存数量。不过，这些启发式方法可能并不总是产生正确的值。在这种情况下，可以使用该变量来改善Volume Rendering模块的性能。
  • AVIZO_MULTISAMPLE：在高端图形系统上，默认使用多重采样视觉。通过这种方式实现了高效的场景抗锯齿。如果你想禁用该功能，请把环境变量AVIZO_MULTISAMPLE设为0。请注意，在其他系统上（特别是PC上），抗锯齿无法由应用程序控制，而必须直接在图形驱动程序中激活。
  • AVIZO_NO_LICENSE_MESSAGE：默认情况下，当你的Avizo许可证即将到期时，Avizo会向控制台发出警告消息。这使你能够及时采取行动，以免在许可证到期时你对Avizo的使用被意外中断。要禁用这些消息，请把该变量设为1。
  • AVIZO_NO_OVERLAYS：如果设置了该变量，Avizo将不会在其3D图形窗口中使用覆盖平面。同样的效果也可以通过-no_overlays命令行选项获得。如果你在远程显示上重定向Avizo时遇到问题，或者你的X服务器不支持覆盖视觉，请关闭覆盖平面。
  • AVIZO_NO_SPLASH_SCREEN：如果设置了该变量，Avizo在初始化期间将不显示启动画面。
  • AVIZO_LOCAL：指定包含用户自定义模块的本地Avizo目录的位置。在该目录中定义的IO例程或模块会替换主Avizo目录中所定义的那些。该环境变量会覆盖在开发向导中所设置的本地Avizo目录（详情参见Avizo程序员指南）。
  • AVIZO_SMALLFONT：仅Unix系统。如果设置了该变量，即使屏幕分辨率为1280x1024或更高，Properties Area中所显示的所有端口也会使用小字体。默认情况下，只在分辨率较小时才使用小字体。
  • AVIZO_XSHM：仅Unix系统。如果你想抑制在Avizo的Segmentation Editor中使用X共享内存扩展，请把该变量设为0。

  • AVIZO_SPACEMOUSE（已弃用）：该功能已被弃用。如果Avizo找到一个已连接的设备，默认情况下Spacemouse支持是可用的（参见 http://www.3dconnexion.com ）。如果驱动程序已安装，控制台窗口中会打印一条消息。使用spacemouse，你可以在3D查看器窗口中导航。支持两种模式：旋转模式和飞行模式。你可以通过按下spacemouse的按钮1或2在两种模式之间切换。在Avizo.init文件中可能提供更多配置选项。

    3Dconnexion Spacemouse的限制：

    • Spacemouse支持在Mac OS X上不可用。
    • Spacemouse被Avizo/AvizoInline应用程序识别。
    • 六自由度运动尚未得到完全支持。
    • Spacemouse只能控制第一个查看器。
    • 在旋转模式下无法平移相机或上下移动。
    • 在飞行模式下无法绕对象旋转或上下移动。
    • 默认情况下，按钮1用于打开”菜单”，必须把它重新配置为”Button 1”功能。按下该按钮可设置旋转模式。
    • 默认情况下，按钮2未被设为”Button 2”功能。按下该按钮可设置飞行模式。
  • AVIZO_STEREO_ON_DEFAULT：如果设置了该变量，3D查看器默认将以OpenGL原始立体模式打开。通过这种方式，可以避免在从单视场切换到立体模式时本来会出现的某些屏幕闪烁。目前，该变量仅在Unix系统上受支持。
  • TMPDIR：该变量指定临时数据应被存储在哪个目录中。如果未设置，此类数据将在/tmp下创建。除其他用途外，该变量会被Avizo的作业队列所解释。

11.3.3 用户自定义启动脚本

可以通过提供一个用户自定义的启动脚本，以某些方式定制Avizo。默认的启动脚本名为Avizo.init，位于Avizo安装目录的子目录share/resources/Avizo中。每次程序启动时都会读取该脚本。除其他事项外，该启动脚本负责注册文件格式、模块和编辑器，以及加载默认颜色图。

如果在当前工作目录中找到一个名为Avizo.init的文件，则会读取该文件而不是默认的启动脚本。如果找不到这样的文件，在Unix系统上会检查用户主目录中是否存在一个名为.Avizo的启动脚本。

一个用户自定义启动脚本的示例大致包含以下内容：先用source $AVIZO_ROOT/share/resources/Avizo/Avizo.init 0执行系统的默认启动脚本；然后用viewer 0 setBackgroundMode和viewer 0 setBackgroundColor设置均匀的黑色背景；用help setFontSize为帮助浏览器选择非默认的字体大小；最后定义一个proc onKeyF3 { } { ... }过程，在其中调用viewer setCameraOrientation、setCameraPosition和setCameraFocalDistance来恢复相机设置。

在这个示例中，系统的默认启动脚本首先被执行。这确保所有Avizo对象都被正确注册。然后进行一些特殊设置。最后，为功能键[F3]定义了一个热键过程。你也可以为任何其他功能键定义这样的过程。此外，还可以定义诸如onKeyShiftF3或onKeyCtrlF3之类的过程。这些过程会在按下功能键并同时按住[SHIFT]或[CTRL]修饰键时被执行。

11.5 TCL脚本编写

本节描述如何在Avizo中使用TCL脚本编写。

11.5.1 脚本编写简介

本章仅面向高级Avizo用户。如果你不知道什么是脚本编写，那么很可能你并不需要本章所描述的功能。

除了通过图形用户界面进行交互式控制之外，Avizo的大部分功能也可以使用特定命令来访问。这使你能够自动化某些流程，并创建用于管理例行任务或进行演示的脚本。Avizo的脚本命令基于Tcl，即Tool Command Language。这意味着你可以使用带有Avizo特定扩展的Tcl来编写命令脚本。

Avizo命令可以被键入到Avizo控制台窗口中，如第10.1.13节所述。直接键入控制台窗口的命令会被立即执行。此外，命令也可以被写入一个文本文件，之后作为整体执行。

本章的组织如下：

第11.5.2节（Tcl简介）给出Tcl脚本语言的简短介绍。本节不太具有Avizo特定性。

第11.5.3节（Avizo脚本接口）说明与脚本编写相关的Avizo特定命令和概念。这包括一份全局命令参考。

第11.5.5节（Avizo脚本文件）说明编写和执行脚本文件的不同方式，包括对脚本对象、资源文件和功能键绑定Tcl过程的引用。

第11.5.6节（配置弹出菜单）描述如何使用脚本命令配置某个对象的弹出菜单，以及如何创建导致某个脚本被执行的新条目。

第11.5.7节（注册拾取回调）描述如何把脚本回调附加到对象或查看器上，并在用户拾取事件时被调用。

第11.5.8节（Tcl中的文件读取器）描述如何注册一个用Tcl实现的自定义文件读取器。

第11.5.9节（创建符合配方的脚本对象）描述如何创建一个可用于创建配方的脚本对象。

第11.5.10节（脚本对象的版本管理与向后兼容性）描述向后兼容性方面的考虑，并列出所有带有已弃用端口的模块。

11.5.2 Tcl简介

本章给出Tcl脚本语言的简短介绍。如果你熟悉Tcl，可以跳过本节。不过，请注意：为了向Avizo控制台输出，你应当使用echo命令，而不是puts命令。

此外，你也可以很容易地在互联网上找到Tcl文档和参考手册，例如在 http://www.scriptics.com ，或者用搜索引擎查找Tcl tutorial或Tcl documentation之类的关键词。

当你把Tcl命令键入Avizo控制台时，一按下回车键它们就会被执行。请使用Avizo控制台所提供的补全和历史功能，如第10.1.13节（控制台窗口）所述。

11.5.2.1 Tcl列表、命令、注释

首先，请注意Tcl是区分大小写的：set和Set并不相同。

一条Tcl命令是一个以空格分隔的单词列表。第一个单词代表命令名，所有后续单词都被当作该命令的参数。作为一个例子，试试Avizo特定的命令echo，它会把其所有参数打印到Avizo控制台。

Tcl命令可以用分号(;)或换行符分隔。因此，两条连续的echo命令既可以写在一行内用分号隔开，也可以分写两行。

在Tcl代码中，除了命令之外，你也可以放置注释。注释以井号字符(#)开始，到下一个换行为止结束。

11.5.2.2 Tcl变量

Tcl中可以使用变量。变量代表某个特定的状态或值。使用Tcl代码，可以查询、定义和修改该占位符的值。要定义一个变量，请使用命令：

请注意，在Tcl内部，所有变量都是字符串类型。由于set命令要求恰好一个参数作为变量值，因此你必须为包含空格的值加上引号：既可以用双引号set Output "Hello World"，也可以用花括号set Output {Hello World}。

11.5.2.3 Tcl命令替换

要在Tcl中进行数学计算，你可以使用命令expr，它会对其参数求值并返回该表达式的值。例如expr 5 / ( 7 + 3)或expr $i + 1。

为了在后续命令中使用像expr这样的命令的结果，必须使用一个重要的Tcl机制：命令替换，用方括号[]表示。任何被方括号[]括起的列表都会先作为一条独立的命令被执行，然后[...]这个构造会被该命令的结果所替换。这类似于Unix命令外壳中的'...'构造。例如，为了把变量i的值增加1，你可以使用set i [expr $i + 1]。

当然，命令表达式可以任意嵌套。执行顺序总是从最内层的方括号对到最外层，例如echo [expr 5 * [expr 7 + [expr 3+3]]]。

11.5.3.3 性能增强

在一个多次创建/应用模块的脚本中，可能会出现性能问题。这可能是由于历史记录(History Logging)造成的——它被用于从模块结果创建配方(Recipes)。

允许你指定不同的背景图案。如果mode设为0，将显示均匀背景。模式1表示渐变背景。对应于棋盘图案的模式2已被移除。最后，模式3会把先前用setBackgroundImage定义的一幅图像绘制在背景上。

返回当前的背景模式。

该命令允许你把任意一幅栅格图像插入到查看器背景的中央。该图像不得大于查看器窗口本身，否则它会被裁剪。图像文件的格式会通过查看文件名扩展名自动检测。除Encapsulated PostScript之外，snapshot命令中提到的所有格式都受支持。如果指定了第二个图像文件，在活动立体渲染的情况下，该文件将被用作右眼图像。如果指定了-stereo选项而只给出了一个图像文件，则假定该文件包含左眼视图和右眼视图并排合成的画面。随后这些视图会被自动分离。

viewer getBackgroundImage

该命令返回用setBackgroundImage定义的最后一个背景图像文件的文件名。如果指定的是一对立体图像，则返回两个文件名。如果在setBackgroundImage中使用了-stereo选项，该选项也会被返回。

viewer [<number>] setAutoRedraw <state>

如果state为0，则自动重绘模式被关闭。在这种情况下，除非发送了重绘命令，查看器窗口中显示的图像将不会被更新。如果state为1，则自动重绘模式重新被打开。在脚本中，临时禁用自动重绘模式可能是有用的。

viewer [<number>] isAutoRedraw

如果自动重绘模式已打开，则返回真。

viewer [<number>] redraw

该命令强制当前场景被重绘。只有在自动重绘模式已被禁用的情况下，才需要显式的redraw。

viewer [<number>] rotate <degrees> [x|y|z|m|u|v]

绕某个轴旋转相机。要采用的轴由第二个参数指定。可用的选择如下：

  • x：x轴 (1,0,0)
  • y：y轴 (0,1,0)
  • z：z轴 (0,0,1)
  • m：x、y或z中最接近垂直的那个轴
  • u：查看器的上方向
  • v：观察方向

最后一个选项与用户界面的旋转按钮作用相同。在大多数情况下，m选项最为合适。为了向后兼容，默认值是u。

viewer [<number>] setDecoration <state>

已弃用。

viewer [<number>] saveScene [-b] [-r] [-z] <filename>

把某个查看器中所显示的全部几何体以Open Inventor 3D图形格式保存。警告：由于许多Avizo模块使用了自定义的Open Inventor节点，该场景通常无法在诸如ivview之类的外部程序中被正确显示。可用的选项如下：

  • -b：以二进制格式保存Open Inventor文件。
  • -r：不仅保存某个查看器中所显示的几何体，还把额外的属性一并保存到Open Inventor文件中。
  • -z：以压缩格式保存Open Inventor文件（使用zip压缩）。

viewer [<number>] viewAll

重置相机，使整个场景变为可见。对于在某个查看器中显示的第一个对象，该方法会被自动调用。

viewer [<number>] show

该命令打开指定的查看器，并确保该查看器窗口显示在屏幕上所有其他窗口的最上方。

viewer [<number>] hide

该命令关闭指定的查看器。

viewer [<number>] isVisible

该命令指示指定的查看器是否可见。

viewer [<number>] fogRange <min> <max>

设置雾效的衰减范围——雾效可以通过View菜单引入到查看器场景中。默认范围是$[0, 1]$。该范围内的值对应于场景点到相机的距离，因此离相机最近的点值为零，而最远的点值为一。限制衰减范围意味着衰减将从所指定最小值处的点开始，并在所指定最大值处的点达到其最大值。雾的最大衰减等同于不可见，因此超出该最大值的所有点都将显示为背景。

viewer [<number>] setVideoFormat pal|ntsc

按PAL 601或NTSC 601分辨率设置查看器窗口的尺寸，即720x576像素或720x486像素。装饰的当前设置会被考虑在内。

viewer [<number>] setVideoFrame <state>

如果state为1，则在查看器的覆盖平面中显示一个边框。该边框描绘出录制到视频中的图像能够在视频播放器上被安全显示的区域。设置查看state：0则关闭该边框。注意：显示在覆盖平面中的对象不会被snapshot命令保存到文件（见上文）。

viewer [<number>] getViewerSpinAnimation

如果查看器旋转动画已打开则返回1，否则返回0。

如果state为1，则打开查看器旋转动画。否则，把0作为state传入将关闭查看器旋转动画。注意：查看器旋转动画的状态会被保存为首选项，因此在重启Avizo后它仍保持不变。

viewer [<number>] setViewing <state>

设置查看state：0把查看器切换到交互模式，1把它切换到查看模式。

viewer [<number>] getViewing

指示查看状态：0表示交互模式，1表示查看模式。

viewer [<number>] linkViewer [<ID>...]

该命令用于链接查看器。该命令的作用与相应的GUI操作完全相同。

viewer [<number>] unlinkViewer [<ID>...] [all]

该命令用于解除已链接查看器的链接。

命令

11.5.5 Avizo脚本文件

值得注意的是，一个Avizo项目其实就是一个能够重建当前Avizo状态的Tcl脚本。因此，交互式地创建一个Avizo项目、用”Save Project”保存它，然后把它作为编写脚本的起点，往往是很高效的做法。

在Avizo中执行Tcl命令最简单的方式是把它们键入Avizo控制台窗口。不过，对于诸如循环或过程之类的多行构造，这种方式并不实用。在这种情况下，建议把Tcl代码写入一个文件，并用命令source filename执行该文件。你也可以在某个文件内部使用source命令，以便把另一个文件的内容包含进来。
